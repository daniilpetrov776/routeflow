# RouteFlow

Приложение для построения маршрутов с использованием Yandex Maps API.

## Структура проекта

Проект разделен на два отдельных приложения:

- **`client/`** - React клиентское приложение
- **`server/`** - Express серверное приложение
- **`shared/`** - Общие типы и схемы

## Быстрый старт

### 1. Запуск сервера

```bash
cd server
npm install
cp env.example .env
# Отредактируйте .env файл
npm run dev
```

Сервер будет доступен на http://localhost:5001

### 2. Запуск клиента

```bash
cd client
npm install
cp env.example .env.local
# Отредактируйте .env.local файл
npm run dev
```

Клиент будет доступен на http://localhost:3000

## Развертывание

### Сервер

```bash
cd server
npm run build
npm start
```

### Клиент

```bash
cd client
npm run build
# Разверните папку dist на ваш хостинг
```

## Переменные окружения

### Сервер (.env)
- `PORT` - Порт сервера (по умолчанию 5001)
- `DATABASE_URL` - URL базы данных
- `SESSION_SECRET` - Секрет для сессий
- `CLIENT_URL` - URL клиентского приложения
- `NODE_ENV` - Окружение (development/production)
- `YANDEX_MAPS_API_KEY` - API ключ Yandex Maps (обязательно)
- `ALLOWED_ORIGINS` - Разрешенные источники для CORS (через запятую)

### Клиент (.env.local)
- `VITE_API_URL` - URL API сервера
- **Примечание**: API ключ Yandex Maps больше не используется на клиенте. Все запросы проксируются через сервер.

## Технологии

- **Клиент**: React, TypeScript, Vite, Tailwind CSS, Redux Toolkit, React Query, DOMPurify, toast
- **Сервер**: Node.js, Express, TypeScript, Drizzle ORM, Winston, express-rate-limit
- **Общее**: Zod для валидации

### ⚠️ Критические проблемы безопасности

#### 1. Раскрытие API ключей ✅ ИСПРАВЛЕНО
**Проблема**: API ключ Yandex Maps передавался на клиент через `VITE_YANDEX_MAPS_API_KEY`
- **Риск**: Ключ виден в исходном коде клиента, может быть украден
- **Решение**: 
  - ✅ Создан эндпоинт `/api/yandex-maps/config` на сервере для получения конфигурации
  - ✅ Клиент запрашивает конфигурацию с сервера вместо использования переменной окружения
  - ✅ Все API ключи теперь хранятся только на сервере
  - ✅ Создана утилита `server/lib/api-keys.ts` для централизованного управления ключами

#### 2. Отсутствие валидации входных данных ✅ ИСПРАВЛЕНО
**Проблема**: API роуты не использовали Zod схемы для валидации
- **Риск**: SQL injection, XSS, некорректные данные, переполнение памяти
- **Решение**: 
  - ✅ Создан файл `server/lib/validation-schemas.ts` с схемами валидации для всех API роутов
  - ✅ Добавлена валидация для `/api/geocode` (query параметр `address`)
  - ✅ Добавлена валидация для `/api/suggest` (query параметр `text`)
  - ✅ Добавлена валидация для `/api/routes` (body с `startingPoint`, `destinations`, `transportMode`)
  - ✅ Все входные данные проверяются на тип, длину, диапазон значений
  - ✅ Ошибки валидации возвращаются с понятными сообщениями (HTTP 400)
  - ✅ Защита от переполнения: ограничение количества пунктов назначения (максимум 10)
  - ✅ Защита от некорректных координат: проверка диапазонов широты (-90 до 90) и долготы (-180 до 180)

#### 3. Отсутствие rate limiting ✅ ИСПРАВЛЕНО
**Проблема**: Нет ограничения частоты запросов
- **Риск**: DDoS атаки, злоупотребление API
- **Решение**: 
  - ✅ Добавлен `express-rate-limit` middleware для защиты от злоупотреблений
  - ✅ Создан файл `server/lib/rateLimiter.ts` с конфигурациями лимитов для каждого роута
  - ✅ Общий лимит: 200 запросов/минуту для всех API endpoints (защита от DDoS)
  - ✅ Специфичные лимиты для каждого роута:
    - `/api/suggest`: 100 запросов/минуту (мягкий лимит, учитывает дебаунс при вводе)
    - `/api/geocode`: 30 запросов/минуту
    - `/api/routes`: 20 запросов/минуту (средний лимит для тяжелой операции)
    - `/api/yandex-maps/config`: 10 запросов/минуту (строгий лимит для редко используемого endpoint)
  - ✅ Все превышения лимитов логируются через Winston logger
  - ✅ Возвращаются понятные сообщения об ошибках на русском языке (HTTP 429)

#### 4. Использование console.error вместо logger ✅ ИСПРАВЛЕНО
**Проблема**: В `server/routes/geocode.ts`, `suggest.ts`, `routes.ts` использовался `console.error`
- **Решение**: 
  - ✅ Все `console.error` заменены на `logger.error()` и `logger.warn()`
  - ✅ Ошибки валидации логируются как предупреждения (warn)
  - ✅ Критические ошибки логируются как ошибки (error)

#### 5. Отсутствие санитизации HTML ✅ ИСПРАВЛЕНО
**Проблема**: Данные из API могут содержать небезопасный HTML
- **Риск**: XSS атаки через внедрение вредоносного кода в данные от внешних API
- **Решение**: 
  - ✅ Установлена библиотека `DOMPurify` для санитизации HTML
  - ✅ Создан файл `client/src/lib/sanitize.ts` с утилитами для санитизации:
    - `sanitizeHtml()` - для санитизации HTML контента (разрешает только безопасные теги: b, strong, i, em, u, br, p)
    - `sanitizeText()` - для экранирования HTML символов в обычном тексте
  - ✅ Применена санитизация во всех местах отображения данных из API:
    - `address-suggestions.tsx` - санитизация title и subtitle при отображении предложений
    - `map-markers.ts` - санитизация HTML в balloonContent маркеров (критично для безопасности)
    - `geocoding.ts` - санитизация адреса при получении из API
    - `useAddressSuggestions.ts` - санитизация данных при обработке предложений
    - `route-card.tsx` - санитизация адреса при отображении в карточке маршрута
  - ✅ Все данные из Yandex Maps API теперь безопасно обрабатываются перед отображением

  - ✅ Определены типы для всех используемых объектов:

    - `YandexPlacemark` - маркеры на карте

    - `YandexMapsNamespace` - глобальный объект ymaps
    - И другие вспомогательные типы
  - ✅ Заменены все `any` типы на строгие типы в файлах:
    - `map-markers.ts` - типизированы функции создания маркеров
    - `map-container.tsx` - типизированы refs для карты и маршрутов
    - `useRouteCalculation.ts` - типизированы параметры хука и работа с маршрутами
    - `use-yandex-maps.ts` - убран `@ts-ignore`, используется типизация
  - ✅ Добавлено расширение глобального интерфейса `Window` для `window.ymaps`
  - ✅ Улучшена типобезопасность и автодополнение в IDE

#### 3. Дублирование логики ✅ ИСПРАВЛЕНО

**Проблема**: Логика получения API ключа и обработки ошибок дублировалась в роутах
- **Решение**: 
  - ✅ Создана утилита `server/lib/api-keys.ts` для получения API ключа (уже существовала)
  - ✅ Создана утилита `server/lib/yandex-api.ts` для работы с Yandex API:
    - `buildGeocoderUrl()` - создание URL для Geocoder API
    - `buildMapsScriptUrl()` - создание URL для загрузки Maps API
    - `fetchGeocoderData()` - выполнение запросов к Geocoder API
  - ✅ Создана утилита `server/lib/error-handlers.ts` для обработки ошибок:
    - `handleValidationError()` - обработка ошибок валидации Zod
    - `handleError()` - обработка общих ошибок
  - ✅ Обновлены все роуты для использования новых утилит:
    - `suggest.ts` - использует `fetchGeocoderData()` и `handleValidationError()`
    - `geocode.ts` - использует `fetchGeocoderData()` и `handleValidationError()`
    - `routes.ts` - использует `handleValidationError()`, убран неиспользуемый API ключ
    - `yandex-maps.ts` - использует `buildMapsScriptUrl()` и `handleError()`
  - ✅ Устранено дублирование кода, улучшена поддерживаемость

#### 4. Отсутствие обработки ошибок ✅ ИСПРАВЛЕНО

**Проблема**: Некоторые места не обрабатывают ошибки должным образом
- `use-yandex-maps.ts`: Ошибка загрузки скрипта не обрабатывается в UI
- `useRouteCalculation.ts`: Ошибки расчета маршрутов не показываются пользователю
- **Решение**: 
  - ✅ Создана утилита `client/src/lib/error-toast.ts` для централизованной обработки ошибок:
    - `showMapLoadError()` - для ошибок загрузки карты
    - `showRouteError()` - для ошибок расчета маршрутов
    - `showError()` - для общих ошибок (кастомные случаи)
  - ✅ Добавлена обработка ошибок через toast-уведомления в `use-yandex-maps.ts`:
    - Ошибка получения конфигурации с сервера
    - Ошибка загрузки скрипта Yandex Maps API
    - Ошибка загрузки конфигурации
  - ✅ Добавлена обработка ошибок через toast-уведомления в `useRouteCalculation.ts`:
    - Ошибка отсутствия Yandex Maps API
    - Ошибка некорректных координат начальной точки
    - Ошибка некорректных координат пунктов назначения
    - Ошибка расчета отдельных маршрутов
    - Общая ошибка, если не удалось рассчитать ни один маршрут
  - ✅ Настроено автоматическое скрытие toast-уведомлений через 5 секунд с плавной анимацией
  - ✅ Все ошибки показываются пользователю на русском языке с понятными сообщениями
  - ✅ Toast-уведомления используют общий дизайн проекта (variant: "destructive" для ошибок)
  - ✅ Устранено дублирование кода - все ошибки обрабатываются через единые утилиты
